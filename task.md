Ниже требования к **Letcalc** в форме задания: что считается сделанным, как устроен язык и какие темы нужны на каждый слой. База рассчитана на пять дней. `if` и присваивание вынесены отдельно и базу не меняют.

## Что должно получиться

Интерактивный цикл читает строку, разбирает её в дерево выражения и вычисляет. Разбор и вычисление — чистые функции. `IO` есть только в цикле чтения и печати.

К концу базы цикл считает такие строки:

```text
2 + 3 * 4
let x = 10 in x - 3
let x = 2 in let y = x * 5 in y + 1
(1 + 2) * 3
```

Успех печатает одно целое. Ошибка печатает непустое сообщение, цикл продолжается. Строка `:q` завершает цикл. Пустая строка пропускается.

Строка `:trace <программа>` печатает и число, и трассу шагов. Так результат `Writer` виден снаружи.

## Границы модулей

Один cabal-проект:

| Модуль | Содержимое |
|---|---|
| `src/Parser.hs` | монада и комбинаторы |
| `src/Expr.hs` | дерево выражения |
| `src/Parse.hs` | грамматика языка поверх `Parser` |
| `src/Eval.hs` | вычисление |
| `app/Main.hs` | цикл |
| `test/Main.hs` | законы и контрольные строки |

`Parser` не знает про `Expr` и `Eval`. `Eval` не импортирует `IO` и не читает строку. Готовые библиотеки разбора (`Text.Parsec`, `megaparsec`, `attoparsec`) не используются: экземпляр монады пишется свой. `Data.Map` для окружения допустим.

## Язык

Пробелы и табы между лексемами игнорируются, внутри числа и имени — нет.

```text
program  = expr , конец строки
expr     = "let" , name , "=" , expr , "in" , expr
         | sum
sum      = product , { ("+" | "-") , product }
product  = atom , { ("*" | "/") , atom }
atom     = integer | name | "(" , expr , ")"
name     = буква латинского алфавита , { буква или цифра }
integer  = цифра , { цифра }
```

`let`, `in` — ключевые слова, их нельзя использовать как имена. `+` и `-` левоассоциативны и слабее `*` и `/`. `*` и `/` левоассоциативны. Унарного минуса нет: отрицательное число записывается как `0 - n`.

Разбор успешен только если строка прочитана целиком. `1 2`, `let x = 1 in`, пустая программа — ошибка разбора.

Числа — `Integer`. Деление — целочисленное `div`, остаток отбрасывается. Округление к нулю или вниз для отрицательных чисел в базовых тестах не проверяется: контрольные примеры неотрицательные.

Внутренний `let` перекрывает внешнее имя. После `in` внешнее связывание снова видно:

```text
let x = 1 in let x = 2 in x    →  2
let x = 1 in (let x = 2 in x) + x    →  3
```

Неизвестное имя — ошибка, в тексте есть это имя. Деление на ноль — ошибка, в тексте есть `zero` или `деление`.

Трасса пишется после вычисления детей, в таком виде:

```text
<левый> <операция> <правый> = <результат>
<имя> = <значение>
let <имя> = <значение>
```

Для `let x = 2 in let y = x * 5 in y + 1` успешная трасса содержит, в этом порядке:

```text
x = 2
2 * 5 = 10
let y = 10
y = 10
10 + 1 = 11
let x = 2
```

При ошибке вычисления сохранять трассу не требуется.

## Компонент 1. Монада `Parser`

```haskell
newtype Parser a = Parser { runParser :: String -> Either String (a, String) }
```

Нужны экземпляры `Functor`, `Applicative`, `Monad` и комбинаторы `satisfy`, `char`, `string`, `many`, выбор из двух альтернатив (`<|>` или свой `orElse`), а также

```haskell
counted :: Parser a -> Parser [a]
```

`counted p` читает неотрицательное целое `n` и затем `n` раз применяет `p`. Второй разбор зависит от значения первого, поэтому здесь нужен `>>=`: одним `<*>` это не выразить.

Последовательный разбор в `Parse.hs` записывается через `do` или `>>=`. Ручной вызов `runParser` внутри грамматики не используется.

Проверки на равных входах, через `runParser`:

- `return a >>= k` совпадает с `k a`
- `m >>= return` совпадает с `m`
- `(m >>= k) >>= k'` совпадает с `m >>= (\x -> k x >>= k')`

Достаточно двух-трёх парсеров: `char`, `string` и парсер, который падает на пустой строке.

Темы:

- `newtype`, отличие от `data` в том, как прячется функция прогона
- стрелка Клейсли `a -> Parser b` и смысл `>>=` как «остаток строки передали дальше»
- раскрытие `do` в `>>=` и `\x -> ...`
- `fmap` через монаду: `fmap f m = m >>= (return . f)`
- законы монады и что именно они гарантируют для остатка строки
- `pure` и `<*>`: грамматики, где форма продолжения не зависит от уже прочитанного значения
- `Either String` как та же форма, что `Maybe`, только с текстом ошибки
- почему левая рекурсия вида `expr = expr "+" term` не завершается и как от неё устроены слои `sum` / `product`

## Компонент 2. Грамматика

`parseExpr :: String -> Either String Expr` возвращает дерево только когда остаток пуст. Непустой остаток — ошибка разбора.

```haskell
data Expr
  = Lit Integer
  | Var String
  | Add Expr Expr
  | Sub Expr Expr
  | Mul Expr Expr
  | Div Expr Expr
  | Let String Expr Expr
```

Имена конструкторов можно выбрать свои, набор тот же.

Темы:

- алгебраический тип как синтаксическое дерево
- рекурсивный спуск по слоям приоритета
- левоассоциативность: `8 - 3 - 1` — это `(8 - 3) - 1`, свёртка списка термов слева
- ключевое слово и имя: сначала попытка `let`, потом имя; откат альтернативы, если слово не подошло
- позиция ошибки: в `Left` достаточно непустого текста, точное место в строке не требуется

## Компонент 3. Вычисление в `Either`

Сначала функция без классов из `transformers`:

```haskell
eval :: Env -> Expr -> Either String Integer
```

`Env` — список пар или `Map String Integer`. Неизвестное имя и деление на ноль дают `Left` и не вычисляют соседнюю ветку дальше. Для `let x = 1 / 0 in 5` результатом будет ошибка деления, не `5`.

Темы:

- `Either` как монада: `Left` обрывает цепочку `>>=`
- тотальная функция вместо частичного `div`: ошибка видна в типе
- обход дерева сопоставлением с образцом
- неизменяемое окружение: внутренний `let` считает тело в расширенной копии, внешний вызов свою среду не меняет
- перекрытие имени и область после `in`

## Компонент 4. `Reader`

Та же семантика вторым вычислителем:

```haskell
evalR :: Expr -> ReaderT Env (Either String) Integer
```

`eval` можно оставить и выразить через `runReaderT`. Контрольные строки обязаны совпадать у обоих.

Темы:

- `Reader r a` как функция `r -> a`, которую `>>=` склеивает сам
- `ask`, `local`: `local` расширяет среду на время тела `let` и возвращает прежнюю снаружи
- `ReaderT` и `runReaderT`: внутренний эффект здесь `Either String`
- порядок стека: `ReaderT Env (Either String)` означает «среда есть и при ошибке, но ошибка не несёт среду»
- чем это отличается от явного аргумента `Env -> ...`: тип тот же, протягивание аргумента спрятано в `>>=`

Для базы `State` не нужен. Связывание `let` не меняет среду соседей, оно только подставляет другую среду в поддерево. Это как раз `local`.

## Компонент 5. Трасса и цикл

```haskell
evalRW :: Expr -> WriterT [String] (ReaderT Env (Either String)) Integer
```

Список строк — моноид. Запись шага делается после шагов детей. Формат строк задан выше. `:trace` печатает их по одной после числа.

Цикл:

- читает строку
- `:q` заканчивает работу
- пустая строка — новый виток
- `:trace ` снимается с начала, дальше та же программа, печать числа и трассы
- иначе печать числа или текста ошибки
- после ошибки цикл жив

Темы:

- моноид списков: `mempty` — пустой лог, `<>` — дописать хвост
- `Writer w a` как пара «значение и накопленное», `tell`
- `WriterT` снаружи `Either`: при `Left` пары с логом нет, поэтому сохранять трассу при ошибке не требуется
- `IO`: `getLine` и печать только в `Main`, чистые функции остаются чистыми
- рекурсивный цикл или `forever` плюс явный выход
- `>>` там, где результат шага не нужен (напечатать и пойти дальше)

## Проверки

Отдельная проверка на каждый закон монады для `Parser` и на каждую контрольную строку: и значение, и факт ошибки. Для `:trace`-программы из раздела про трассу — отдельная проверка порядка строк. Запуск: `cabal test`.

## Дополнительно, после базы

Сравнения и ветвление. Грамматика расширяется так:

```text
expr = "if" , comparison , "then" , expr , "else" , expr | let | sum
comparison = sum , ("<" | ">" | "==") , sum
```

Обе ветки разбираются всегда. Вычисляется одна. `if 1 / 0 < 2 then 1 else 0` — ошибка деления. `if 0 < 1 then 1 else 1 / 0` даёт `1`. В дерево добавляются конструкторы сравнения и `If`. В трассу попадает только выбранная ветка и само сравнение, например `1 < 2 = True`.

Темы: ленивость тут ни при чём, ветку отбрасывает сам вычислитель; `Bool` в результате сравнения, при этом итогом программы по-прежнему остаётся `Integer`.

Присваивание, если хочется увидеть `State`. Одна форма, `set name = expr in expr`: сначала считается правая часть, затем тело в среде, где имя уже обновлено. Это уже изменение среды для всего хвоста, а не подстановка на время поддерева.

```haskell
StateT Env (Either String) Integer
```

Темы: `get` и `put` (или `modify`); чем `State` отличается от `Reader` на одном и том же `Env`; зачем базе хватало `local`.

Лямбды, вывод типов и готовый парсер-комбинатор в это задание не входят. Их имеет смысл брать отдельной задачей уже поверх этой монады.
